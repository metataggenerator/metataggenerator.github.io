Canonical Tags: Fix Duplicate Content the Right Way

The same content often appears at more than one address: a product page with tracking parameters, a printer-friendly version, a page reachable with and without a trailing slash, or the same article on two domains. Search engines see those as separate pages, and the ranking value splits between them. The canonical tag fixes that by pointing every copy at one original.

This guide explains what a canonical tag is, when to use it, how to write it correctly, and the mistakes that make it useless.

What a canonical tag is

A canonical tag is a link element in the head of a page: <link rel="canonical" href="https://example.com/original-page/">. It tells search engines that this page is a copy or a variant, and that the ranking value should go to the address in the href. It is a hint, not a command, but Google follows it in most cases.

Every page should have a canonical tag pointing at itself, even when there is no duplicate. That self-referencing canonical protects the page when someone links to a version with tracking parameters, because the tag tells Google the clean address is the real one.

When to use a canonical tag

Use it when the same or very similar content appears at multiple URLs: product pages with sort or filter parameters, the same article in two categories, an HTTP and an HTTPS version, or a page with and without 'www'. Also use it for syndicated content: if another site republishes your article, their copy should carry a canonical tag pointing at your original.

Do not use a canonical tag as a substitute for a redirect when a page is permanently gone: use a 301 redirect instead. And do not use it to point at a different page with different content, because Google will ignore a canonical that does not match.

How to write it correctly

Use the full absolute URL, including the protocol and domain, and make it the address you want in search results. Put the tag in the head of every version of the page, including the original, where it points at itself. Make sure the canonical address returns a 200 status and is not blocked by robots.txt or a noindex tag.

If you use an SEO plugin, it usually adds canonical tags automatically. Check that the plugin's address matches the address you actually want indexed, especially after changing domains, moving to HTTPS, or changing permalink structures.

Common canonical mistakes

The most common mistake is a canonical tag that points at a page that redirects, or at a 404 page. Google ignores those. The second mistake is conflicting signals: a canonical pointing one way and internal links pointing another. The third is using relative URLs, which can resolve to the wrong address on some pages.

Another mistake is pointing many pages at one category page in the hope of combining their ranking value. Canonical tags are for duplicate content, not for unrelated pages. If the content is different, each page should be canonical to itself.

Key takeaways

  • Every page should have a self-referencing canonical tag.
  • Use absolute URLs and point at the address you want in search results.
  • Use canonical tags for duplicates; use 301 redirects for pages that are gone.
  • Check for conflicts: internal links and canonical tags should agree.

Frequently asked questions

What is a canonical tag?

A link tag in a page's head that tells search engines which address is the original version, so ranking value is not split between duplicates.

Is a canonical tag the same as a redirect?

No. A redirect sends visitors and crawlers to a new address. A canonical tag leaves the page in place but tells search engines which version to credit.

Should every page have a canonical tag?

Yes, a self-referencing one. It protects the page when someone links to a version with tracking parameters or a trailing slash.

The Viewport Meta Tag: Why Every Mobile Page Needs One

Open a website on a phone and it should fit the screen: text readable, buttons tappable, no sideways scrolling. That behaviour depends on one small tag in the head of the page: the viewport meta tag. Without it, mobile browsers assume the page was designed for a desktop and shrink it to fit, leaving tiny unreadable text.

This guide explains what the viewport tag does, the one line every responsive site needs, and the settings you should and should not use.

What the viewport tag does

A viewport is the visible area of a web page on a device. Desktop browsers have wide viewports; phones have narrow ones. The viewport meta tag tells the browser how wide the page's viewport should be and how it should scale. Without the tag, a phone browser uses a default viewport of about 980 pixels and shrinks the page to fit the screen.

With the tag, the browser uses the device's actual width, and your responsive CSS can do its job: stacking columns, resizing images, and adjusting text. The tag is what makes responsive design possible.

The one line every site needs

The standard tag is: <meta name="viewport" content="width=device-width, initial-scale=1">. The width part sets the viewport to the device's width. The initial-scale part sets the starting zoom to 100 percent, so the page is neither zoomed in nor zoomed out when it loads.

Put this tag in the head of every page, on every site, without exception. It is one of the first things Google checks in its mobile-friendly test, and a page without it is treated as not mobile-friendly, which can hurt its mobile rankings.

Settings to avoid

Older advice suggested disabling zoom with user-scalable=no or setting a maximum scale. Do not do that. It prevents people with poor vision from zooming in to read your page, and it is an accessibility failure. Google and accessibility guidelines both advise against disabling zoom.

Also avoid setting a fixed width, such as width=1024. A fixed width breaks the page on any device narrower than that value, which is most phones. The device-width value exists precisely so you do not have to guess screen sizes.

How to test your viewport tag

Open your site on a real phone and check that text is readable without zooming and that no horizontal scrolling is needed. Then run Google's mobile-friendly test or the mobile usability report in Search Console, which flags pages with viewport problems.

If the page renders as a tiny desktop layout on a phone, the viewport tag is missing or wrong. View the page source, find the head section, and check the tag. It takes a minute to fix, and the improvement is immediate.

Key takeaways

  • Every page needs: width=device-width, initial-scale=1.
  • Without the tag, phones shrink the page to a 980-pixel desktop layout.
  • Never disable zoom: it blocks people with poor vision from reading your page.
  • Test on a real phone and in Google's mobile-friendly test.

Frequently asked questions

What is the viewport meta tag?

A tag that tells mobile browsers how wide the page's viewport should be. It is what makes responsive design work on phones.

What happens if a page has no viewport tag?

Mobile browsers assume a desktop-width page and shrink it to fit, leaving tiny unreadable text and forcing sideways scrolling.

Should I disable zoom with user-scalable=no?

No. It prevents users with poor vision from zooming in, and it is an accessibility failure that Google advises against.

The Robots Meta Tag: Control Indexing Page by Page

Most pages on a website should appear in search results. Some should not: admin pages, thank-you pages, duplicate content, internal search results, and staging pages. The robots meta tag is the tool for keeping those pages out, one page at a time.

This guide explains the robots meta tag, the values it accepts, the mistakes that cause pages to vanish from search by accident, and when to use a robots.txt file instead.

What the robots meta tag does

The robots meta tag sits in the head of a page and gives instructions to search engine crawlers. The most common values are 'index' and 'noindex', which allow or block indexing, and 'follow' and 'nofollow', which allow or block following the links on the page. A typical tag looks like <meta name="robots" content="noindex, follow">.

Search engines treat these instructions as strong hints, and Google follows them reliably. The tag only works if the crawler can reach the page: if the page is blocked in robots.txt, the crawler never sees the tag, and the page may stay in the index anyway.

The values you can use

The full set of common values is index, noindex, follow, nofollow, noarchive, nosnippet, noimageindex, and max-snippet. Noarchive stops Google showing a cached copy. Nosnippet stops the page's text appearing in search snippets. Noimageindex keeps the page's images out of image search. Max-snippet limits how many characters of the page Google may show.

Combine values with commas, such as 'noindex, nofollow' for a page that should be neither indexed nor followed. The default for a page with no robots tag is 'index, follow', so you only need the tag when you want to change that default.

Common uses

Use noindex on thank-you pages, login pages, cart and checkout pages, internal search results, and tag or filter pages that duplicate other content. Use noimageindex on pages whose images are private. Use nosnippet on pages with content you do not want quoted in results, such as a paywalled article's preview.

Use max-snippet when you want a page to appear in results but with only a short preview, for example to protect a recipe or a list that people should visit the page to see. These are all small, precise tools: use the smallest restriction that does the job.

Mistakes to avoid

The most damaging mistake is putting noindex on a page that should rank, often by copying a staging site's tags to the live site. Audit your important pages after any migration or redesign, and check that noindex appears only where you intended it. A single wrong tag can remove a page from Google for weeks.

The second mistake is combining noindex with a robots.txt block. If the crawler cannot fetch the page, it cannot see the noindex tag, and the page may remain in the index as a bare URL. For a page you want gone, allow the crawl and use noindex, or remove the page and let it return a 404.

Key takeaways

  • Use noindex for pages that should not appear in search: logins, carts, thank-you pages.
  • The tag only works if the crawler can fetch the page, so do not block it in robots.txt too.
  • Combine values like noindex, nofollow or noimageindex for precise control.
  • Audit important pages after migrations: a stray noindex can hide a page for weeks.

Frequently asked questions

What does noindex do?

It tells search engines not to include the page in search results. The page can still be visited directly by anyone with the link.

Can I use the robots meta tag and robots.txt together?

Carefully. If robots.txt blocks the page, the crawler never sees the noindex tag. For a page you want removed, allow the crawl and use noindex.

How long does it take for noindex to work?

Usually days to a few weeks. Google must recrawl the page and process the tag before the page drops out of results.
